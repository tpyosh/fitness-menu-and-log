# Garmin Connectログ取得

ユーザーのコピペや確認を減らし、取れた情報で役に立つ記録を残して終える。欠損は許容し、未確認の事実は作らない。

## 対象と取得

1. 発言と既存文脈から、対象日・URL・activity ID、実施メニュー、取得のみか記録までかを読む。「今日BをやったのでGarminから記録して」はBの記録、「昨日のログを取って」「このURLの内容を確認して」は取得のみ。今日・昨日はAsia/Tokyoの依頼日を基準に絶対日付へ解決する。既に分かることを聞き直さない。
2. Safariを既定に、`cua_repl`の**ネイティブアプリ操作**を使う。Safariでは初回に `await cua.getApp("Safari")` だけを実行し、返った最新の操作説明に従う。別ブラウザの明示指定があればその指定と現在のツール説明に従う。適切な既存タブがなければ新規タブを使う。非公開API、Cookie抽出、ページ内JavaScriptや独自ブラウザ基盤は使わない。
3. URL指定ならその詳細、日付指定なら[Activities一覧](https://connect.garmin.com/app/activities)から候補を探す。画面の日付・時刻・種目と詳細URLのactivity IDを照合する。TODAY等は絶対日付と照合し、日付とURLが食い違う、または複数候補を区別できない場合だけ短く確認する。対象を確定できないまま記録しない。
4. アクセシビリティの文字情報を優先し、必要箇所だけ読む。操作後の状態から次の操作を選び、過去の要素番号・座標を流用しない。画像は文字で読めない必要箇所だけに絞る。Stats等の時間・心拍・TE・負荷・カロリー・Primary Benefitから進め、Laps・Time in Zonesは容易に読める範囲で追加する。画面名や構成は変わり得る。
5. 主要値を含め、読めない項目は欠損でよい。読み込み不良では、状態再取得など短い復旧を1回程度試し、進展がなければ取得済みの情報で終える。ツールの再取得制約を優先し、既知の復旧方法があるとは扱わない。ログイン画面ならSafariでのログインだけ短く依頼し、その回は待ちとして終える。ツールが使えない場合も未取得と伝えて終え、多数の画像・手動コピペ・再試行を求めない。

## 結果と記録への接続

- 取得のみでは正本・rawファイルへ書き込まず、対象、読めた値、取得元URL・ID・取得日時、必要な欠損を返す。何も読めなければ未取得とする。過去の検証値を今回取得した値として使わない。
- 記録依頼なら、[構造化ログの取得元・重複規約](../../../data/logs/structured/README.md#garmin-connectの取得元と重複確認)で**追加前に重複を確認**し、読めた表示値と本人申告を [record-garmin-session](../record-garmin-session/SKILL.md)へ渡す。保存・処方解決・比較・フィードバックはそちらで行い、再実装しない。取得項目ゼロなら処方だけでGarminログを新規作成しない。
- CardioはA/B/Cの証拠にならず、Total Sets 1は種目別set数ではない。メニューやCモードが文脈から決まらず記録分類に必要な場合だけ確認する。取得のみならメニューを聞かない。処方継承と観測事実は分ける。
- 質問は対象の取り違え、記録に必要なメニュー特定、安全や次回判断が実質的に変わる欠損に絞る。痛み・RPE・筋肉痛・全setの回数を一律に聞かず、未申告を「痛みなし」にしない。判断だけ未確定・条件付きにできる。危険症状はリポジトリの安全方針を優先する。
- 総時間・ラップ・ゾーンは表示どおり保持する。1秒程度の差や合計不一致で止めず、必要なら短く注記し、原因や補正値・残差の割当てを作らない。
- 通常の返答は「何を取得／記録できたか」と、記録時は根拠のある「次回への短い一言」を中心にする。欠損は必要なら一言。部分取得、記録済み重複、ログイン待ち、操作失敗を完全取得・保存成功と呼ばない。

トークン計測は明示的な検証依頼時だけ行う。実測できなければ測定不能とし、過去の計測値を通常1件のコストとせず、キャッシュ済み入力を無料・利用枠消費ゼロと扱ったり料金・利用枠消費率へ換算したりしない。
